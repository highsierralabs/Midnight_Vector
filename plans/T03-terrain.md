## 1. Purpose

After T03 a viewer of `dev/terrain.html` sees the picture this product is built around: a black mirror floor under a glowing magenta grid, wire-lined mountains framing a banded sun in a V, a rippling sun column on the floor, accent pulses running up the grid, all fading into the sky with no visible end. Observable outcomes:

1. The look holds at every distance. Frames at world 0, 1e9, 1e12, 1e15 and the world limit have been opened and described by the executor, as near, mid and far crops, and they show the same picture.
2. No crack, ever. No sky pixel appears under terrain over 900 frames per configuration at 150 u/s, and enlarging the coarse hole by 4 cells makes the same detector report hundreds of thousands of pixels.
3. No visible end of the world. With 21:9, FOV 68 and full bend, every terrain boundary pixel has `fogK` exactly 1, and lengthening the fog by a little makes the same test fail. The same holds at 16:9 and 16:10 with the camera at the lane wall under DI-88's follow gain, while a camera x far outside the lane fails it (A9c).
4. The far grid is stable. Rows under the horizon converge to their expected mean coverage, stay under the bloom threshold, and frame-to-frame change in rows 615 to 650 is at most 8/255, while a naive grid exceeds that.
5. It is exact. A periodic world gives 0 differing bytes between frames 1e15 u apart with post off.
6. It is cheap. 120,456 triangles in 6 draws, row streaming p99 at or below 2 ms, one rebuild at or below 30 ms, and only one program for the terrain.

Terms:

- **Level `k`**: one of six nested copies of one grid, spacing `s = 2 * 2^k` (2, 4, 8, 16, 32, 64 u).
- **Lattice row**: absolute integer row of a level. Lattice row `q` of level `k` is at world z `q * s`, forward positive. Rows can be negative near chunk 0, because rear rows lie behind the camera.
- **Grid vertex**: `position = (c, r, 0)` with integer column `c` in 0..128 and grid row `r` in 0..96. Shared by every level.
- **Atlas**: one RGBA32F texture, 129 wide, 768 tall, 128 rows per level. R is true height, G is morph height.
- **Slot**: atlas row within a level, lattice row mod 128.
- **Base row**: lattice row of grid row 0, always even.
- **Forward (`zf`)**: distance ahead of the camera along the road. Render z is `-zf`.
- **Morph**: per-vertex blend from R to G, so a level equals its parent's mesh in its outer band.
- **Hole**: cells removed from a level so its parent's finer child shows through.
- **Overlap**: band between the hole edge and the fine footprint edge. **Drop**: the small epsilon that lowers a coarse level so it loses the depth test there.
- **Stride**: 1 draws every cell; 2 draws 2x2 cells on even vertices only (tiers 1 and 0).
- **Boundary cell**: outermost cell of level 5 on a side or at the far row. Nothing is drawn beyond it.
- **Crest**: with `c < 0` the bent floor's highest image row, below the geometric horizon. See section 10.
- **Stand-in sky**: a T03 dev-only sky drawn from contract GLSL, because T04's sky is a sibling. **Ref height**: a T03 dev-only copy of the exact §4.4 and §5.2 function.
- **Rehearsal**: throwaway code run on 2026-11-05 in the session scratchpad, with three 0.187.0 and the §8 GLSL, on the RTX 4070 SUPER and SwiftShader. Numbers marked **[O]** in this plan come from it. It is not part of the project and may be gone, so none of it counts as acceptance. The executor runs everything again.

### M1. Layout and geometry, pure

**Goal:** the mesh is right before it is drawn. **Work:** `layout.ts` and `geometry.ts` per section 4.

`buildIndex(stride, hole, grow)`, with `W = 129`:

```ts
const h = stride === 1 ? HOLE : HOLE_S2;
const c0 = h.c0 - grow, c1 = h.c1 + grow, r1 = h.r1 + grow;
for (let r = 0; r < 96; r += stride) for (let c = 0; c < 128; c += stride) {
  if (hole && r < r1 && c >= c0 && c < c1) continue;
  const a = r * W + c, b = a + stride, d = a + W * stride, e = d + stride;
  out.push(a, b, d, b, e, d);       // pre-sized array in practice
}
```

The shared edge `b`-`d` is the uniform diagonal from `(c + 1, r)` to `(c, r + 1)`, which is what the morph rule in §6.4 assumes. The winding is CCW from above [arithmetic: (b - a) x (d - a) has +y].

Triangle counts: stride 1, 24,576 full and 19,176 holed, total 120,456 (§6.4). Stride 2, 6,144 full and 4,824 holed, total 30,264 [O].

**Hole position (§6.4):** rows `[0, 45)`, columns `[34, 94)`. These are the spike's bounds [O: `r < holeR && c >= C/2 - holeC && c < C/2 + holeC`]. Margin to the fine footprint [arithmetic, every phase of both levels]:

| Level | Lateral | Forward | Rear, behind the camera so never visible |
|---|---|---|---|
| 1, 2, 3 | 2 cells | 3 to 4 cells | hole overruns by 0 to 1 cell |
| 4, 5 | 2 cells | 4 to 5 cells | hole overruns by 1 to 2 cells |

`uRowOffset` ranges, level 0 to 5: `(-36, -32]`, `(-40, -32]`, `(-48, -32]`, `(-64, -32]`, `(-128, -64]`, `(-256, -128]` [arithmetic].

**Result:** tested pure code. **Proof:** A1.

### M2. Atlas, pure

**Goal:** heights and morph values correct, in a ring, with no allocation. **Work:** `AtlasWriter`, one per layer:

- State: `written[k]`, highest even lattice row written (start `-Infinity`); `low[k]`, lowest live row; `prevEven[k]`, a `Float64Array(129)` of the last even row's heights; scratch `tmpOdd`, `tmpEven`. All allocated in the constructor.
- `needsRefill(cam)`: any level where `baseRow + 96 - written > 128`, or `baseRow < low`.
- `refill(cam)`, per level: `start = baseRow - 2`; evaluate row `start` into `prevEven` and write it as an even row; `written = low = start`; then pairs up to `baseRow + 96`. That is 99 rows, under the ring's 128.
- Pair step, as §6.4: `q = written`; evaluate `q + 2` into `tmpEven`, `q + 1` into `tmpOdd`; write odd row `q + 1` with `lo = prevEven`, `hi = tmpEven`; write even row `q + 2`; copy `tmpEven` into `prevEven`; `written = q + 2`; if `written - low >= 128`, then `low = written - 127`.
- Morph, exactly §6.4. Even row: `G = c odd ? 0.5 * (h[c-1] + h[c+1]) : h[c]`. Odd row: `G = c even ? 0.5 * (lo[c] + hi[c]) : 0.5 * (lo[c+1] + hi[c-1])`.
- Row placement: `slot = ((q % 128) + 128) % 128`, `atlasRow = slot + k * 128`, texel offset `atlasRow * 129 * 4`. Never `|0` or shifts on `q`.
- `advance` calls `onRow(atlasRow)` once per written row. The layer maps that to `addUpdateRange(atlasRow * 129 * 4, 129 * 4)` per `Agents.md`. It allocates one small object per row, at most about 3 per frame at 150 u/s. §9.2 accepts that rate.

```glsl
in vec3 vP; in vec3 vL; in float vH; in float vF;
uniform float uMirror;
uniform float uPulsePhase[1], uBeatPhase[1];
void main() {
  vec3 rel = vP - cameraPosition; float dist = length(rel); vec3 rd = rel / dist;
  vec3 n = cross(dFdx(vL), dFdy(vL)); float nl = length(n);
  vec3 N = nl > 1e-12 ? n / nl : vec3(0., 1., 0.); N *= N.y < 0. ? -1. : 1.;   // NaN guard, then face up

  vec2 uv = vec2(vL.x, vF + uTravel.x);
  vec2 g8 = pristineLines(uv / 8., vec2(.03)), g64 = pristineLines(uv / 64., vec2(.0075));
  float gl8 = mix(g8.x, 1., g8.y), gl64 = mix(g64.x, 1., g64.y);
  float v = vF + uTravel.y;
  float pulse = exp(-fract(v / 512. - uPulsePhase[0]) * 14.);
  float aU = abs(vL.x), road = 1. - smoothstep(21., 22., aU);
  // road: edges at +-22, centre dashes every 16 u, 40% duty [A]
  float edgeL = pristineLines(vec2((vL.x + 22.) / 44., 0.), vec2(.0114, 0.)).x * (1. - smoothstep(23., 24., aU)) * (1. - rise);

  float dash = da.x * da.y * (1. - smoothstep(1., 2., aU));

  vec3 c = mix(uPal[0] * .16, uPal[1] * .20, hk) + uPal[4] * .05 * hk * hk;
  float sl = clamp(dot(N, normalize(vec3(0., .25, -1.))), 0., 1.);
  c += mix(uPal[1], uPal[2], hk) * sl * sl * sl * .32 * rise + uPal[2] * smoothstep(.55, 1., hk) * .05;

  c += emit(uPal[6], 1.4) * edgeL + emit(uPal[3], 1.2) * dash * .8;               // [A]
  float F = .05 + .95 * pow(1. - max(-rd.y, 0.), 5.);
  float rip = .0035 * (sin(TAU * v / 4096. * 53.) + sin(TAU * v / 4096. * 19.));  // periods 4096/k [A]
```
