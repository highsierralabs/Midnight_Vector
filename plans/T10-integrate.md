## 1. Purpose

After T10 there is one website. A person opens a URL and sees the game. Observable outcomes:

1. **It runs as one thing.** `npm run build` produces a static site. Opened from any path on any static host, it shows a CSS sunset for a moment, then a live neon valley with the title over it, flown by the autopilot, with no input and no audio until a real gesture.
2. **R1 is proven in a browser.** In one real-time page, `travel` strictly rises through DEMO, PLAY, CRUISE, `SIGNAL_LOST`, reduced motion and a context loss and restore, and also after warps to 1e9 u and 1e15 u. The same detector fails when the loop is deliberately stopped.
3. **The frame loop is §3.3, exactly.** A unit test records every call of a frame and compares it to the list in §3.3. Reordering any two steps fails it. No mode, menu or overlay can skip `sim.step`.
4. **Nothing kills the page silently.** No WebGL2 or no float buffers shows the poster and never fetches the engine. A shader error, a runtime exception or a context that never returns shows the fatal page. A restored context resumes the picture without a compile hitch later. A resize or a rotation is correct on the next frame.
5. **T09's suites are armed and pass.** `app/` implements `HarnessHost`, `window.__mv` exists under `?harness`, and `npm run test:forever` and `npm run test:perf` pass on the integrated build. T10 is not done until they do (§12).
6. **Someone has actually looked at it.** The first integrated build has been viewed as stills, as filmstrips and as slit-scan time slices that make pops and flicker visible in a single image, and a real-time recording exists for the operator. Each image has a written description. Numbers do not stand in for this.
7. **Defects went to their owners.** Every fault found in another task's paths is in this plan's register with a repro, and was fixed by that task's reopened plan. A file hash baseline shows T10 changed nothing it does not own.

## 5. Plan of work

Milestones run in order. Each can be verified alone. Expect the first integrated runs to fail. That is what this task is for, and each failure goes through the defect process below.

### Defect routing (standing procedure, every milestone)

**Rule.** T10 edits only its `owns` list. A fault elsewhere is never patched, wrapped or masked from `src/app/`, even by one character. §12 and `Agents.md` Deviations set this.

1. **Reproduce twice.** Prefer a deterministic repro: `?harness`, fixed `seed`, `renderState(c, l, t)`, or a Node script. Save the evidence under `test-results/T10-defects/D-NNN/`.
2. **Rule out T10 first.** Check the order trace, the values in `view` for that frame through the hook, and whether a boot or restore step ran. If the fault is in T10's paths, fix it here with a regression test. No register row.
3. **Attribute it** by the bisect table. Use the narrowest tool that separates owners.
4. **Reduce it** to a repro that does not need T10's code where possible: a `dev/<module>.html` query, or a Node snippet. Then add a failing regression to T10's own tree, `tests/unit/app/defects/D-NNN.test.ts` or a named test in `tests/e2e/`. The owner's fix must turn it green. A regression that T10 cannot write is stated, with the reason.
5. **Record it** as a row in the register in section 10, with all columns. Finish the rest of the current acceptance pass first where it can still run, so that an owner gets all of its defects together, not one per reopen.
6. **Block.** Set this plan to `status: blocked`, with the D-ids and the owners in Progress, and bump `updated`. Report to the operator or the orchestrating reviewer: "reopen T##, see D-NNN in `plans/T10-integrate.md`".
7. **The owner fixes it.** Its plan goes back to `in-progress` with a revision note citing the D-id. The fix stays in its paths, its own acceptance is re-run, and its plan returns to `done`. T10 does not review the diff or suggest code beyond the evidence.
8. **T10 resumes.** Set `in-progress`, refresh the hash baseline for the owner's paths and note it in the row, re-run the failing gate, then continue. The final M9 pass re-runs everything, because a fix can move other gates. Mark the row `verified`.

| Symptom | Bisect tool | Likely owner |
|---|---|---|
| `travel` flat, speed below floor, wrong mode, rule wrong | Unit trace of §3.3 passes? Then a Node run of `createSim(createWorld(...))` | T02, or T10 if the trace fails |
| Wrong height, prop placement, zone, palette values | `world.*` calls in Node at the same chunk; compare with `createFakeWorld` run through the same layer | T01 |
| Wrong picture on one object class | `host.layers[i].setVisible(false)` per layer, then `dev/<module>.html` with the same frame | The layer owner, T03, T04, T05 or T06 |
| Right with `post.forceVariant('off')`, wrong with post on | Each variant through `forceVariant` | T06 |
| Shader failure | `SHADER_ERROR` console text names the program; match the material's `name` | That material's owner |
| Crack, far-edge flash | T03's own detector on `dev/terrain.html` with `createWorld` | T03 |
| Pop, stale object, vanishing after restore | `counters.rebuilds`, `updateRanges` after `rebuild`, FIFO against `rebuild` at the same chunk | T05 or T03; T10 if `rebuild` was not called |
| HUD, title, menu, overlay, input | `dev/ui.html` with the same `scriptedFrame` | T08 |
| Audio wrong, silence, burst | `dev/audio.html` | T07 |
| `__mv` result disagrees with the host | `host.spec.ts` passes? Then T09. It fails? Then T10 | T09 or T10 |
| A gate fails, but the gate looks wrong | Its negative control. A gate with a false result is a defect in the gate's owner, never a threshold edit here | T09, T00, or the owner of that spec |
| Compile mid-game | `compile.spec.ts` names the new program | Owner of that material, or T06 |
| Hitch on a zone or tier change | `hook.counters`, then a CDP profile at the moment | Whoever owns the top frame in the profile |

**Seam defects.** If two tasks each match their own plan but disagree, compare their seam tables. The side that deviates from what it stated owns the fix. If both follow what they stated and the meaning itself is wrong, T10 records it as a `seam` row, proposes the meaning, and the T00 owner decides as the operator's delegate. If the fix needs a contract change, it goes through section 12 of the raising plan and T00.

### M4. Lifecycle

**Goal:** §10 holds on the integrated build. **Work:** `lifecycle.ts`.

**Context loss.** `webglcontextlost`: `flags.contextOk = false`, `restoreGen += 1`, start the 15 s timer (§10.2), then `ui.showContextLost(true)`, so a throw from T08's call cannot remove the safety net (VI-r1; `tests/unit/app/lifecycle.test.ts`). Three calls `preventDefault` [O]. `webglcontextrestored`:

```text
clear timer; counters.restores += 1; gen = restoreGen
if a tier change is held: view.quality = governor.profile; setQuality on layers and post
every layer.rebuild(view); post.rebuild()
await post.precompile()
if gen !== restoreGen: return             // lost again while compiling; the newer event owns recovery
flags.contextOk = true; flags.restorePending = true; ui.showContextLost(false)
```

`restorePending` makes the next body's step 10 rebuild again, because the sim moved on during the `await` while layer frames were skipped. It is defensive: A12r showed every layer heals the same move by itself, 0 bytes with and without it (section 11, 2026-11-06). Timer expiry: `onFatal('context-lost-permanent')`. The loop keeps running throughout, and steps 3 to 9 and 13 to 15 are not gated. Never recreate the renderer (§10.2).

**Fatal route** (`onFatal(r, e)`): once only. `dead = true`, `caf(handle)`, clear the timer, `console.error('FATAL', r, e)` unless `r` is `context-lost-permanent`, `root.dataset.mvBoot = 'running'`, each of `input.detach()`, `audio.dispose()` in its own `try`, `ui.showFatal(r)`, `canvas.remove()`. `audio.frame` and `ui.frame` then never run again. No `renderer.dispose`, which could touch a dead context; the tab is finished and Reload is the exit.

**Hidden tab.** `visibilitychange`: hidden calls `audio.suspend()`. Shown calls `loop.resetClock()` and `audio.resume()`. T07 adds no listener of its own (T07's seam). T08's input clears held keys itself.

**Resize.** `createSizing(stage)`: a `ResizeObserver` on the stage wrapper, observing `{ box: 'device-pixel-content-box' }` inside `try`, and `content-box` in the `catch` (§10.5). Plus `window` `resize` and `visualViewport` `resize`. For a change of `devicePixelRatio` alone, which fires none of those (VI-r1): a `matchMedia('(resolution: <ratio>dppx)')` change listener that re-registers on the new ratio, and a `DPR_POLL_MS` (250 ms) timer that marks dirty when the ratio differs from the one last applied. Under CDP emulation only the timer fires [O: section 9, 2026-11-06]. Each only sets `dirty`, at event time, so the frame reads no extra DOM property. `applyIfDirty(camera, post)`, in step 9: read `stage.clientWidth`, `stage.clientHeight`, ignore under 1 px, `camera.aspect = w / h`, `updateProjectionMatrix`, `gainX = followGainX(aspect)`, `post.resize(w, h, window.devicePixelRatio)`, `counters.resizes += 1`.

**The observed box gives the trigger only, never the ratio.** Under Playwright's `deviceScaleFactor`, `devicePixelContentBoxSize` equalled the CSS size while `devicePixelRatio` was 2, 1.5 or 3 [O], so a ratio taken from the box would render every emulated DPR at 1 and hide DPR bugs. A real display's ratio is the same number [M]. The canvas itself is not observed, because T06's `renderer.setSize` pins its inline size in px, so a shrinking window would never fire on it [I].

**Result:** the robustness section is real. **Proof:** A12 to A17.

## 8. Idempotence and recovery

- Safe to re-run: every check, test and capture here. `dist.spec.ts` overwrites `dist/`. `view.spec.ts` writes only under `test-results/T10-view*`. Playwright clears its own `--output` folder at each start, so T10 never shares one between runs whose evidence must survive.
- Test-only state: `localStorage` lives in Playwright's per-test contexts, and T08 refuses to write bests once `warpSerial` is non-zero, so nothing leaks into the next run.
- Clean state without git: `Remove-Item -Recurse -Force dist, test-results\T10* -ErrorAction SilentlyContinue`. Never delete a sibling's folder under `test-results\`.
- Before a risky rewrite of `src/app/`, copy it outside the project: `Copy-Item -Recurse src\app "$env:TEMP\t10-app-backup"`. There is no git to revert with. Drills restore from their backup and then re-run the named test green.
- Reaching a clean state in `src/app/`: delete it and `src/main.ts` and `index.html`, and re-run from M1. Nothing else depends on their intermediate forms.
- The hash baseline can be rewritten only after an owner's reopened fix, with the D-id noted, never to make A34 pass.
- Never run `npx playwright install`, `npm install`, `npm audit fix` or `git init` here.
